Todo texto que lee un agente es una posible orden.

La seguridad no depende de que el modelo obedezca, sino de lo que el sistema le permite hacer.

Pausa dramática. Una página web, un correo, un PDF o el resultado de una herramienta pueden contener instrucciones. El modelo no distingue con certeza entre "datos" e "instrucciones". Por eso las defensas que funcionan limitan el daño posible en lugar de confiar en que el modelo resista.

4.2 · Inyección indirecta

La tríada letal

Datos privados

Archivos, claves, variables de entorno.

+

Contenido no confiable

Historias de usuario, web, PDF, resultados de herramientas.

+

Comunicación externa

En tu fábrica: desactivada, sin WebFetch ni WebSearch.

Con las tres presentes, una inyección puede exfiltrar datos. Diseña para romper al menos una.

Concepto: Simon Willison, «The lethal trifecta for AI agents», 2025

15 minutos. Inyección directa: el usuario intenta manipular al agente. Indirecta: la orden llega escondida en contenido que el agente lee. Hoy no existe un filtro que detecte el 100% de las inyecciones; por eso la defensa principal es arquitectónica. Si un agente lee contenido no confiable, que no tenga acceso a datos privados o que no pueda comunicarse hacia fuera sin aprobación. Nuestra fábrica de código la reúne por diseño: lee una historia no confiable, accede a archivos y ejecuta el código que genera. El Lab 4 la ataca y luego la rompe.

15 minutos. Defensa en profundidad: cada capa asume que la anterior puede fallar. Recorrer cada una mostrando el archivo donde vive. Los hooks de rol siempre están activos; los de seguridad (lectura confinada, comandos permitidos, auditoría) se apagan con DEFENSAS=0 únicamente para demostrar el ataque en el laboratorio. Pregunta para la clase: ¿por qué un hook es más confiable que escribir "no leas .env" en el prompt? Porque el prompt es una sugerencia que una inyección puede anular; el hook es código que el modelo no puede saltarse.

seguridad/hooks.py

Un hook bloquea antes de actuar

def comandos_permitidos(base: Path, programas: set[str]):
    async def hook(input_data, tool_use_id, context):
        comando = input_data["tool_input"].get("command", "")
        if "`" in comando or "$(" in comando:
            return _denegar(input_data, "Sustitución de comandos no permitida")
        if any(p in comando.lower() for p in PALABRAS_SECRETAS):
            return _denegar(input_data, "El comando menciona secretos")
        for tramo in re.split(r"&&|\|\||;|\|", comando):
            partes = tramo.strip().split()
            if partes and partes[0] not in programas:
                return _denegar(input_data, f"Programa no permitido: {partes[0]}")
        return {}
    return hook

Pregunta: ¿por qué esto es más confiable que una frase en el prompt?

Se registra con HookMatcher(matcher="Bash", hooks=[comandos_permitidos(app, PROGRAMAS)]). Este hook corre antes de cada comando de terminal que Claude Code quiera ejecutar. Rechaza sustituciones de comandos, cualquier mención de secretos o variables de entorno, y cualquier programa que no esté en la lista del rol: el despliegue solo puede usar docker y curl; el automatizador, python y pytest. Si devuelve deny, el comando no se ejecuta y el motivo regresa al modelo, que ajusta su plan. Respuesta esperada a la pregunta: el prompt es una sugerencia que una inyección puede anular; el hook es código determinista que el modelo no puede saltarse.

10 minutos. Después del despliegue y de escribir las pruebas, el flujo las ejecuta todas: API y end to end. Si pasan, se escribe el reporte. Si fallan, el triage, que es el único supervisor de la fábrica, lee los fallos y los criterios de aceptación y devuelve un diagnóstico estructurado: responsable, causa, criterio de referencia e instrucción. El flujo enruta la corrección al agente responsable y vuelve a probar, con un máximo de dos ciclos; después, el reporte escala a una persona. Regla: si la prueba y la app no coinciden, gana quien siga el criterio de aceptación.
