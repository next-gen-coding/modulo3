Red en código: todos con Command a todos

class Turno(BaseModel):

    aporte: str

    siguiente: Literal["analista", "tester", "desarrollador",

                       "revisor", "FIN"]

 

def par(nombre: str):

    def nodo(s: Estado) -> Command[Destino]: # Destino = todos

        t = modelo().with_structured_output(Turno).invoke(...)

        fin = t.siguiente == "FIN" or s["turnos"] >= MAX_TURNOS

        return Command(goto=END if fin else t.siguiente, update=...)

    return nodo

 

for nombre in ROLES:

    grafo.add_node(nombre, par(nombre))

grafo.add_edge(START, "analista") # la única arista fija

Lo que lo distingue

Todos los nodos devuelven Command hacia cualquier otro. Sin aristas fijas, el tope de turnos es obligatorio.

Compáralo con

Supervisor: misma pieza (Command), pero solo en un nodo.

Ejecútalo

python -m ejemplos.s3_topologias.red

En tu fábrica

No la usamos: con pasos conocidos, un grafo fijo es más predecible y barato.

Fragmento simplificado de ejemplos/s3_topologias/red.py · las líneas resaltadas son el patrón

Ejecutar dos o tres veces: el recorrido cambia en cada ejecución. Eso es lo flexible y también lo difícil de depurar. Mostrar el contador de turnos al final. Ejercicio: subir MAX_TURNOS a 30 y ver cuánto cuesta; muchas veces los agentes no deciden terminar solos. Conclusión: misma pieza de código que el supervisor, distinta distribución del poder de decisión.
