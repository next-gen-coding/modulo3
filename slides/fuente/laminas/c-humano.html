def aprobar(s: Estado) -> Estado:

    for x in s["con_aprobacion"]:

        decision = interrupt({"accion": x["tipo"], "empleado": emp,

                              "pregunta": "¿Apruebas? (si / no)"})

        estado = "APROBADA" if decision == "si" else "RECHAZADA"

        log.append(f"{estado} por una persona · {x['tipo']}")

    return {"bitacora": log}

Lo que lo distingue

interrupt pausa y muestra la evidencia, el checkpointer guarda el estado y Command(resume=…) reanuda en el mismo thread_id.

Compáralo con

Plan-and-Execute (sesión 1): allí la aprobación era un input() sin estado guardado.

La solicitud tiene dos acciones: un cambio de puesto, que el código clasifica como de bajo riesgo y se ejecuta solo, y una baja, que se detiene. Responder «no» la primera vez y mostrar la bitácora: la baja queda RECHAZADA por una persona. Señalar que el flujo realmente se pausa: el programa podría terminar y reanudarse más tarde con el mismo thread_id si el checkpointer fuera persistente, por ejemplo con SQLite. Pregunta: ¿qué pasa si quitamos el checkpointer? LangGraph no tiene dónde guardar el estado y interrupt falla.
