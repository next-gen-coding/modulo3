1.3 · Salidas estructuradas y verificación

El agente propone; el validador decide

Contrato

Gherkin para los criterios; JSON con esquema Pydantic para los casos.

Evaluador determinista

validar_gherkin y validar_plan: reglas en código, no otro LLM opinando.

Reflexión guiada

Los problemas regresan al agente para corregir; máximo 2 intentos.

problemas = validar_gherkin(destino.read_text())
if not problemas:
    return destino
tarea += "Tu versión anterior tiene estos problemas; corrígelos: ..."

Sesión 1 · Patrones: ReAct en el bucle, reflexión aquí y Plan-and-Execute en la sesión 2

15 minutos. Este es el principio que guía todo el módulo: cada agente termina en una verificación hecha por código. Los artefactos tienen formato fijo porque son el contrato entre agentes: el diseñador lee el Gherkin del analista, y el automatizador de la sesión 3 leerá el JSON del diseñador. El validador no es otro modelo: son reglas verificables, como que cada escenario tenga Dado, Cuando y Entonces, o que cada escenario tenga al menos un caso. Si falla, los problemas regresan al agente; eso es el patrón de reflexión, con un límite de intentos.
