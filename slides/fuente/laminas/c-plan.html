Plan-and-Execute en código: dos fases

class Plan(BaseModel):

    pasos: list[str]

 

def planificar(tarea: str) -> Plan: # FASE 1

    resp = cliente.messages.create(..., tools=[esquema_plan],

        tool_choice={"type": "tool", "name": "plan"})

    return Plan.model_validate(resp.content[0].input)

 

def ejecutar(tarea: str, plan: Plan) -> str: # FASE 2

    avance = ""

    for i, instruccion in enumerate(plan.pasos, 1):

        avance += llamar(f"{avance}\nHaz SOLO: {instruccion}")

    return avance

 

plan = planificar(tarea)

if input("¿Aprobar el plan? ") == "si": # control humano

    ejecutar(tarea, plan)

Lo que lo distingue

El plan es un dato (Pydantic) que se puede revisar y aprobar antes de gastar en ejecutarlo.

Compáralo con

ReAct: allí no hay plan; cada vuelta decide la siguiente.

python -m ejemplos.s1_razonamiento.plan_ejecucion

Ejecutar y, cuando pregunte, responder «no» la primera vez: el programa termina sin gastar en la fase 2. Ese es el valor del patrón. Señalar tool_choice: forzar una herramienta es la forma clásica de obtener salida estructurada con el SDK de Anthropic; el esquema sale de Pydantic. Puente: en la sesión 2 la aprobación ya no es input(), sino interrupt() de LangGraph, que permite pausar y reanudar el flujo.
